# 公共数据约定与清洗说明

版本：`online-retail-six-features-v1`。本版为 A 已执行的可复现默认口径，尚未声称 B、C 已确认所有选择。

## 输入、观察范围与分析日期

- 输入：UCI Online Retail 原始 `Online Retail.xlsx`，8 列、541,909 行，不修改原文件。
- 数据原始时间范围：2010-12-01 08:26:00 至 2011-12-09 12:50:00。
- 保留全部国家，不只选择英国；不人为抽样客户。
- 分析日期：保留交易最晚购买日的次日，本次为 **2011-12-10**。
- 日期间隔先归一到日历日期，再相减，不用当前日期，不按相差满 24 小时向下取整。
- 原始金额使用英镑。数量乘单价得到 LineAmount；聚合前不强制按两位小数舍入。

## 顺序清洗规则

每行最多记一个排除原因：按下面顺序命中首条规则。各项是互斥计数，可以相加。

| 顺序 | 原因 | 本次排除行数 |
| --- | --- | ---: |
| 1 | CustomerID 缺失 | 135,080 |
| 2 | CustomerID 非有效数字标识 | 0 |
| 3 | 订单号或商品编号缺失 | 0 |
| 4 | 交易日期无效 | 0 |
| 5 | 数量或单价无法解析、NaN、无穷值 | 0 |
| 6 | 订单编号以 C 开头，不区分大小写 | 8,905 |
| 7 | 数量不大于 0 | 0 |
| 8 | 单价不大于 0 | 40 |
| 9 | 行金额不为有限值 | 0 |
| 10 | 八个原始字段完全重复，保留第一条 | 5,192 |
| 合计 | 排除记录 | 149,217 |

因此：541,909 − 149,217 = **392,692** 条保留交易。

原始数据共 9,288 条 C 开头记录、5,268 条超出首条的完全重复记录。它们与其他排除条件重叠，所以不同于顺序清洗表中的互斥排除计数。原始字段缺失情况见 `results/tables/raw_profile.json`。

说明：

- 仅对标识符去除首尾空格，CustomerID 的数字型 `.0` 后缀归一化；不把编号作为数值特征。
- Description 缺失本身不作为排除条件，因为六特征只依赖商品编号等关键字段。
- 完全重复使用原始 8 列判断，不包含新增 SourceRow 或 LineAmount。
- `SourceRow` 是原始 Excel 中的行号，表头为第 1 行，第一条数据为第 2 行。即使保留数据重新排序，也可据此追溯原始记录。
- `data/excluded_rows.csv.gz` 保存被排除的原始行、SourceRow 和 ExclusionReason。gzip 可用 pandas 直接读取。
- 正向交易和取消记录没有做订单级冲抵、配对净额计算；未移除随后被取消的正向交易。

## 六特征定义

`data/customer_features.csv` 严格为 CustomerID 加下面六列，每客户一行。

| 字段 | 定义 | 类型和单位 |
| --- | --- | --- |
| Recency | 2011-12-10 减该客户最后购买日 | 整数，天，本版至少 1 |
| Frequency | 该客户保留交易中不同 InvoiceNo 的数量 | 正整数，订单数 |
| Monetary | 该客户所有保留交易的 Quantity × UnitPrice 之和 | 正数，GBP，正向记录金额 |
| AvgOrderValue | Monetary / Frequency | 正数，GBP/订单 |
| ProductDiversity | 该客户保留交易中不同 StockCode 的数量 | 正整数，编码数 |
| ActiveDays | 最后购买日减首次购买日 | 非负整数，天；同日购买为 0 |

`ProductDiversity` 目前包括保留的运费、人工收费等特殊 StockCode，不严格等于实体商品种类数。没有擅自按“纯数字编码”过滤：正常商品也可能有字母后缀。候选编码清单见 `results/tables/special_stock_codes.csv`，它不是已判定无效商品列表。

`data/customer_dates.csv` 单独给出 FirstPurchaseDate、LastPurchaseDate，以 CustomerID 关联。

## 真实存在的大额取消问题

例如，本版保留的正向交易 581483 金额为 168,469.60 GBP，12 分钟后存在同客户、同商品、同数量与单价的 C581484 取消记录。541431 的 77,183.60 GBP 正向记录也存在对应特征的取消记录。

所以不能仅凭 Monetary 极高就将客户解释为“高价值忠实客户”。本次保留正向记录，另提供：

- `customer_cancellation_diagnostics.csv`：与六特征表相同客户的取消行数、不同取消订单数、取消金额绝对值。
- `largest_order_cancellation_candidates.csv`：金额最高 20 条保留明细与取消记录的候选对应。要求同客户、商品、数量绝对值、单价，且取消时间不早于销售时间。
- `largest_quantity.csv`、`largest_unitprice.csv`、`largest_lineamount.csv`：各指标最高 20 条保留明细，便于人工检查。

候选对应不证明订单级退款关系，也不是穷尽全部退款的净额表。取消统计不是自动可用于冲抵的净退款金额。若小组决定改用退货冲抵或其他规则，应统一更新版本、重建全部特征，再由三人使用同一版数据。

## 给 B 和 C 的使用约定

B 可以直接使用清洗明细和原始尺度六特征做探索分析、相关性分析，结合取消诊断表核查极端客户。

C 统一决定 log1p、标准化、PCA 和算法调用接口。不要将 CustomerID、SourceRow、日期、Country 或诊断字段直接混入六特征矩阵；不要让每个人各自生成一套标准化数据。

客户按文本 CustomerID 升序输出。合并结果时仍按 CustomerID 关联，不把聚类标签数字当成群体名称，不直接比较不同运行的同号簇。

尚待小组确认：完全重复行是否去重、特殊费用编码是否排除、取消记录是否净额化、预处理与共同算法接口、特征消融组合。本版 CSV 可先用于探索及搭建流程，正式对比前共同固定版本。

## 验证依据

- 所有原始行恰好进入保留或排除集合，两集合不相交。
- 392,692 条保留交易均具有正、有限的数量和单价，且不含 C 开头订单。
- 4,338 位客户 ID 唯一，六特征均为有限值。
- 对保存后的明细逐客户独立重算六特征，使用 Decimal 核对金额。
- Monetary 合计为 **8,887,208.8940 GBP**，与交易明细对账。
- 保存逐步清洗日志、原始情况统计、代码和数据 SHA-256、依赖版本。

实现自检见 `pipeline_checks.json`，独立验证见 `independent_validation.json`。这两个文件均位于 `results/tables/`。
